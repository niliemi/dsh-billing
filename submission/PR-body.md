# Add niliemi/dsh-billing (usage)

Single-entry submission: adds `data/plugins/niliemi__dsh-billing.yml`. Nothing else in this repo is touched.

## What it is

`yoka-dsh-billing` is a DSH plugin that prices token usage and lets you cap it.

- The host half folds a session's token usage into a local ledger (uncached input / output / cache read / cache write, kept per turn+step, replacements not re-additions), multiplies each bucket by the official `@earendil-works/pi-ai` price table (`lib/pricing.json`, generated by `tools/build-pricing.mjs`: 32 providers / 605 models, USD per million tokens), applies an editable rate, and serves the result over local `/plugin-billing/*` HTTP routes.
- The browser half registers one entry in the `conversation.composer.dock` slot, so a chip reading `¥12.36 / ¥50.00` sits on the same row as the composer's context meter. Clicking it opens a panel for top-up, ceiling, rate, guard switch, per-model price overrides and per-session breakdown.
- The ceiling is `min(your ceiling, your top-up)`. When spend reaches it, the host returns `{ kind: "reject" }` from the `agent/pre-step` waterfall, so that turn ends without sending an LLM request — after a confirmation dialog offering a one-off or session-wide override.

Values are stored as tokens plus the model key, never as money: changing the rate or a model price re-prices all history immediately.

## Why `usage`

It reports and limits cost/consumption. It does not render conversation, choose models, or add tools.

## Manifest facts the CI checks

- `package.json` declares **`dsh.bundle`** (`cordis.patch.yml`) and `dsh.client` (`platform: "web"`, `exports["./client"]`).
- No `@deepseek-ai/*` runtime dependency: the host half uses only Node built-ins, the browser half only `require("react")` from the frozen platform modules. So there is no peer range that could silently exclude a prerelease host.
- `files` ships exactly `lib/index.js`, `lib/client.js`, `lib/pricing.json`, `cordis.patch.yml`, `README.md`. The browser bundle needs no build step (hand-written `window.__ModuleLoader__.load` factory).
- Repository has real, working code (not a package that only lists dependencies) and will carry the `dsh-plugin` topic.

## How it was verified

- `node tools/self-test.mjs` → 55 passed / 0 failed (pricing, replacement folding, rate re-pricing, ceiling semantics, over-limit reject, one-off and session overrides, request guard, persistence, route teardown).
- `node tools/self-test-client.mjs` → 38 passed / 0 failed (module shell, slot registration, chip text, panel fields, confirm dialog buttons, effect cleanup).
- Installed into a live DSH profile: `GET /plugin-billing/state` returns 200 with real usage, and the client slot tree shows the `billing` entry active in `conversation.composer.dock` next to the shipped meter.
